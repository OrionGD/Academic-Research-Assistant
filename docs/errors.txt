

# System Analysis Report

## Type-Safe Authentication & Authorization Architecture

## 1. System Overview

The implemented authentication system is an **enterprise-grade, type-safe authorization framework** designed for the ARAS backend application. The system integrates authentication, role-based authorization, and secure multi-tenant data access into a unified architecture. Its design eliminates common TypeScript runtime uncertainties such as undefined authentication states while enforcing strict security policies across all API endpoints. 

The architecture emphasizes five key principles:

* **Type Safety**
* **Authentication Integrity**
* **Role-Based Authorization**
* **Per-User Data Isolation**
* **Maintainable Endpoint Patterns**

By restructuring authentication around wrapper functions and strict type definitions, the system reduces boilerplate code, eliminates runtime authentication errors, and standardizes security across all backend services.

---

# 2. System Architecture

## 2.1 Core Authentication Model

The system is built around a single strongly-typed identity model called **RequestUser**, which represents the authenticated user throughout the backend pipeline.

### Core User Type

```
RequestUser
```

Attributes:

| Field       | Description                            |
| ----------- | -------------------------------------- |
| _id         | Unique MongoDB user identifier         |
| role        | Authorization role ("user" or "admin") |
| email       | Optional email identifier              |
| name        | Optional username                      |
| firebaseUid | Firebase authentication identifier     |
| lastLoginAt | Timestamp of most recent login         |

This centralized user schema ensures consistent identity representation across controllers, middleware, and database queries. 

---

# 3. Authentication Flow

The authentication mechanism follows a structured pipeline.

### Authentication Pipeline

```
Client Request
      ↓
Firebase Authentication Token
      ↓
authMiddleware
      ↓
User Identity Validation
      ↓
RequestUser Object Assigned
      ↓
Authorization Wrapper
(requireUser / requireAdmin)
      ↓
Controller Execution
```

This pipeline guarantees that **all protected endpoints receive a validated user object before business logic executes.**

# 4. Type Safety Architecture

## 4.1 Problem Solved

Traditional Express applications often suffer from runtime errors caused by uncertain authentication states such as:

```
req.user may be undefined
```

This system eliminates that problem through **type-guarded wrappers**.

### Previous Pattern

```
if (!req.user) return unauthorized
```

### New Pattern

```
requireUser(handler)
```

The wrapper ensures:

* Authentication validation
* Error handling
* Type safety enforcement
* Clean endpoint logic

As a result, endpoint code becomes simpler and more reliable. 

---

# 5. Authorization Model

## 5.1 Role-Based Access Control

The system implements a **strict two-role model**:

| Role  | Privileges                   |
| ----- | ---------------------------- |
| user  | Standard platform access     |
| admin | System management privileges |

Admin access is **restricted to a predefined account identity**, preventing privilege escalation. 

### Admin Enforcement Mechanism

Admin verification occurs through:

```
requireAdmin()
```

This wrapper performs:

1. Authentication validation
2. Role verification
3. Automatic audit logging

If the user is not authorized, the system returns a **403 Forbidden response**.

---

# 6. Multi-Tenant Data Isolation

A critical security feature is **per-user data isolation**, preventing users from accessing other users' resources.

### Query Isolation Mechanism

Every database query automatically includes:

```
userId
```

Example concept:

```
Document.find({ userId })
```

The framework introduces helper utilities such as:

```
createUserFilter()
enforceUserIsolation()
```

These utilities guarantee that database operations always remain scoped to the authenticated user. 

---

# 7. Security Mechanisms

## 7.1 Resource Ownership Validation

Beyond query isolation, the system implements **defense-in-depth validation** through resource ownership checks.

```
assertUserOwnsResource(resource, user)
```

This prevents:

* Cross-user data manipulation
* Unauthorized resource access
* Middleware bypass attacks

---

## 7.2 Authentication Error Management

A custom error class standardizes security responses.

```
AuthenticationError
```

Error mapping:

| Error Type   | HTTP Response    |
| ------------ | ---------------- |
| MISSING_USER | 401 Unauthorized |
| INVALID_USER | 401 Unauthorized |
| UNAUTHORIZED | 401 Unauthorized |
| FORBIDDEN    | 403 Forbidden    |

This structured error strategy ensures consistent API responses and simplifies debugging.
